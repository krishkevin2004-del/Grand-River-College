# Product brief

## Goal

Demonstrate how a campus-life assistant can answer recurring student questions, show the source behind the answer, and direct sensitive or unsupported questions to an appropriate next step. The demonstration takes place at fictional Grand River University.

## Student experience

A student enters a question or taps a sample prompt. The app can provide a cited housing answer, list date-specific meals or events, return a directory contact, or open the hall picker. It responds explicitly when a closure, cancellation, or missing record affects the answer. The help entry point remains available during the conversation.

## Launch scope

- 59 resident policy sections across 19 chapters, with a 23-page PDF and a page-aligned index
- Seven residence entries, eleven campus services, and non-dialable fictional numbers
- Three dining venues, 74 dishes and 123 dated meal services
- Fourteen events with prices, RSVP rules, accessibility information and revisions
- A shared UI with responsive chat, citations, anonymous aggregate feedback, and a separate help screen
- Local answers by default and optional model-backed safety and housing answers

The demo has no student accounts, enrollment data, transaction flows, or live feeds. Report any missing source coverage explicitly. Treat this as a portfolio simulation and keep pilot metrics from any prior university project separate.
